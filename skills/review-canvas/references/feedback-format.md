# Local feedback contract

The review input uses `schema_version` 2. Saved feedback uses `feedback_schema_version` 3, not the input schema. Older feedback versions fail with a message that names the version. There is no migration. Keep an older file as earlier manual notes rather than assuming it can restore highlights or approvals.

The strict JSON root contains target, input_sha256, exported_at, general_notes, files, approvals, comments and retained_reviews. The target and input digest describe the captured snapshot. The target is the same object as the input's `target`: a `github_pr` or a `worktree`. Every file entry contains path, status, group and notes. JSON has no patch source except selected quotes and their context; those may still contain private code. Keep exports within the approved audience and do not upload them automatically.

Each approval contains path, fingerprint and approved_at. It records that the reviewer approved one exact version of that file. When a page loads feedback, a file is approved only if the stored fingerprint equals the file's current fingerprint. Otherwise the page shows **Changed since approval**, and the file needs review again. Approvals carry over between snapshots of the same review, so an unchanged file keeps its approval in the next round. Approvals for files outside the current snapshot stay in the file, so a file that returns unchanged is approved again. Approval is display only and blocks nothing.

Each comment contains a stable id, body, created_at, updated_at, anchor, history and attachment. An anchor contains its original snapshot (target and input_sha256), exact path and patch_sha256, start/end offsets, quote, prefix/suffix, start_row/end_row, side and start_line/end_line. Offsets are zero-based UTF-16 code units in the displayed patch rows joined with LF; end is exclusive. Row numbers are zero-based patch rows including hunk headers. `side` is `old` or `new`. A selection of deleted lines, alone or with context, is old-side; any other selection is new-side. `start_line` and `end_line` are source line numbers on that side, from the first to the last selected row that has one. A selection of only a hunk header cannot become a comment. Unicode context avoids split surrogate pairs. A comment needs a pinned target: a PR URL and head commit, or a working tree.

A comment may also contain replies: the reviewer's answers to the agent, in order. Each reply contains a stable id, unique across the feedback, actor `reviewer`, created_at in UTC ISO 8601, body, and action. The action is `accept`, `reopen`, or `reply`. Body text is required except for `accept`. A comment with no replies omits the field. The agent's replies live in the review input, not in feedback. The page merges both into one thread per comment, ordered by time, and derives the thread state from the last reply: no reply is open, an agent reply waits for the reviewer, `accept` resolves the thread, and `reopen` or `reply` returns it to the agent. A reviewer reply with no agent answer before it means the round's input lacks the earlier answers, and the thread shows that instead of a state. Nothing stores the state. Once a thread has replies, the page no longer offers to edit or delete its comment, so an answer always refers to the comment it answered. The page lists agent answers to comments it does not hold, such as a comment deleted before the answer arrived.

The original anchor remains unchanged when the current diff moves. Exact patch digest plus offsets attaches immediately. Otherwise the full selected quote and its adjacent prefix/suffix must match exactly once. Missing paths, absent patches, changed context and ambiguous repeated text produce an orphan. No rename guessing or fuzzy line matching occurs. Attachment is current derived state (attached/orphan, reason and current offsets), recomputed on import; imported attachment claims are never trusted. Manual reattachment retains the prior anchor in history and records the selected current snapshot.

Two snapshots belong to the same review when they have the same target kind and either the same PR URL or the same working tree root. A PR target without a URL matches only its own input digest. Import rejects feedback for another review.

Import is transactional. It validates the entire file before changing the open page. It decodes the file as strict UTF-8, as `feedback_contract.py` does, so malformed bytes or a leading byte order mark reject it. Same-snapshot notes restore; deliberate edited values, including blanks, and conflicting comment IDs are rejected. Reviewer replies merge by ID when one copy of a comment extends the other. Two copies that each hold a reply the other lacks are rejected, because they answered without seeing each other, and so is the same reply ID with different content. Approvals merge by path. When the page and the file both hold an approval for a file, the page keeps the one for the current version, or else the newer one. An approval made in the open tab stays. An approval cleared in the open tab rejects an import that holds an approval for that file. Semantically identical repeated imports are idempotent. Imports from another snapshot of the same review preserve earlier notes under retained_reviews, keeping only the files with notes, while carrying approvals and resolving comments against the current patch. A retained snapshot whose digest matches the open page, as when the code returns to an earlier version, leaves the retained list, and its notes return to the page when the tab has none of its own. An open comment draft must be finished or cancelled before import. Multiple asynchronous imports use the newest selected file; an older read cannot replace it.

Limits:8MiB UTF-8 JSON;2,000 unique files;2,000 approvals with unique paths;1,000 unique comment IDs;20,000 UTF-16 units per note/body/quote;80 units per context side;20 prior anchors per comment;200 reviewer replies per comment;50 unique retained snapshots, the newest kept when a new round adds one;2MiB aggregate note/body/quote text. Past 2,000 approvals, or past 8 MiB as exported, the page drops the oldest approvals for files outside the current snapshot. An import that still exceeds 8 MiB is rejected. Unknown fields, duplicate JSON keys, numbers written with a fraction or exponent, invalid identities/ranges, control characters and unpaired Unicode surrogates are rejected. Lengths and offsets count UTF-16 code units, and "nonempty" means more than JavaScript whitespace. The page's `assets/feedback.js` and the server's `scripts/feedback_contract.py` validate the same contract, and `tests/fixtures/feedback/` holds shared valid and invalid cases that both must pass. Export requests a browser download and displays a copy fallback; a requested download does not prove the file saved, so the unsaved-page warning remains.

The HTML embeds style, fonts, notices and scripts. Opened as a file, it has no fetch or upload, and feedback is only in the tab and manually selected or downloaded files. Served by `serve_review.py`, it saves feedback only to that local server, which writes the review's state directory; see [the server reference](server.md). It never posts comments or runs the agent. localStorage stores only the theme preference. Validate the original pinned source and comment IDs before any separately authorized batch action.
