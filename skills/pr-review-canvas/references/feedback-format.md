# Local feedback contract

The review input stays at schema_version1. Saved feedback uses feedback_schema_version2, not the input schema. Version1 feedback has no inline anchors and is rejected with a version message; keep it as earlier manual notes rather than assuming it can restore highlights.

The strict JSON root contains pr, input_sha256, exported_at, general_notes, files, comments and retained_reviews. PR identity, full head/base commits and input digest describe the captured snapshot. Every file entry contains path, status, group, reviewed and notes. JSON has no patch source except selected quotes and their context; those may still contain private code. Keep exports within the approved audience and do not upload them automatically.

Each comment contains a stable id, body, created_at, updated_at, anchor, history and attachment. An anchor contains its original snapshot (pr and input_sha256), exact path and patch_sha256, start/end offsets, quote, prefix/suffix, start_row/end_row, old_line/new_line. Offsets are zero-based UTF-16 code units in the displayed patch rows joined with LF; end is exclusive. Row numbers are zero-based patch rows including hunk headers, not repository source lines. The old/new source annotations describe the first selected row when available. Unicode context avoids split surrogate pairs.

The original anchor remains unchanged when the current diff moves. Exact patch digest plus offsets attaches immediately. Otherwise the full selected quote and its adjacent prefix/suffix must match exactly once. Missing paths, absent patches, changed context and ambiguous repeated text produce an orphan. No rename guessing or fuzzy line matching occurs. Attachment is current derived state (attached/orphan, reason and current offsets), recomputed on import; imported attachment claims are never trusted. Manual reattachment retains the prior anchor in history and records the selected current snapshot.

Import is transactional. It validates the entire file before changing the open page. Same-snapshot notes and flags restore; deliberate edited values, including blanks, and conflicting comment IDs are rejected. Semantically identical repeated imports are idempotent. Imports from another snapshot of the same PR preserve earlier notes and flags under retained_reviews while resolving comments against the current patch. A reviewed flag on an old commit never becomes a current flag. An open comment draft must be finished or cancelled before import. Multiple asynchronous imports use the newest selected file; an older read cannot replace it.

Limits:8MiB UTF-8 JSON;2,000 unique files;1,000 unique comment IDs;20,000 UTF-16 units per note/body/quote;80 units per context side;20 prior anchors per comment;50 unique retained snapshots;2MiB aggregate note/body/quote text. Unknown fields, duplicate JSON keys, invalid identities/ranges, control characters and unpaired Unicode surrogates are rejected. The save path validates the same limits. Export requests a browser download and displays a copy fallback; a requested download does not prove the file saved, so the unsaved-page warning remains.

The HTML embeds style, fonts, notices and scripts. It has no fetch, upload, comment posting or agent execution. Feedback is only in the tab and manually selected/downloaded files; localStorage stores only the theme preference. Export remains private until the reviewer explicitly hands the file to their agent. Validate the original pinned source and comment IDs before any separately authorized batch action.
